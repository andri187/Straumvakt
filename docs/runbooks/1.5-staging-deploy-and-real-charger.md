# Sprint 1.5 — Staging deploy + real-charger smoke test

This runbook walks through deploying `hlada` (main app) and
`straumvakt-ocpp` (gateway) to Cloudflare staging, pointing a real
charger at the gateway, and verifying the control-plane exit
criterion for Sprint 1.5:

- Heartbeats flow from a real charger to the gateway (`Available` /
  `Preparing` status observable in `ocpp.connectors`).
- A `ChangeConfiguration` command round-trips with the charger's
  Accepted reply landing in the event log as `ocpp.command_result`.
- A follow-up `GetConfiguration` call reads the new value back.
- A `RemoteStartTransaction` command transitions the charger state
  (visible via `ocpp.connectors.status` projection).
- A subsequent `RemoteStopTransaction` closes a zero-energy session
  row, producing a valid CDR (no MeterValues required).

## 0. Preconditions (operator — NOT the assistant)

Do these before deploying:

1. **Create the `straumvakt-ocpp-staging` Worker** (the gateway) in
   the Cloudflare dashboard. It must exist before Service Bindings
   from `hlada-staging` resolve.
2. **Create Durable Object migration class** — Cloudflare will
   auto-create the `IdentityDurableObject` class on first deploy of
   the gateway with the current `gateway/wrangler.jsonc`. Verify in
   dashboard → Workers → straumvakt-ocpp-staging → Durable Objects
   after the first deploy.
3. **Set secrets on `hlada-staging`** (main app Worker):
   - `AUTH_SECRET` — 32-byte random hex (admin session signing)
   - `ADMIN_EMAIL` — your admin email
   - `ADMIN_PASSWORD` — your admin password
   - `DATABASE_URL` — staging Neon branch pooled URL
   - `DIRECT_URL` — staging Neon branch direct URL (for migrations)
   - `OCPP_INGEST_SECRET` — 32-byte random hex (MUST match the
     `straumvakt-ocpp-staging` value below)
4. **Set secrets on `straumvakt-ocpp-staging`** (gateway Worker):
   - `OCPP_INGEST_SECRET` — same value as `hlada-staging` above.
     Nothing else needed; the gateway does not hold DB credentials.
5. **Apply migrations to the staging Neon branch.** From the main
   app root (you, not the assistant):
   ```
   DATABASE_URL="<staging pooled url>" npx prisma migrate deploy
   ```
6. **Seed the staging catalog** (same Zaptec + Zaptec Pro rows as
   dev). From the main app root:
   ```
   DATABASE_URL="<staging pooled url>" npx prisma db seed
   ```

## 1. Deploy

From the main app root (`/`):

```
npx opennextjs-cloudflare build
npx wrangler deploy --env staging
```

From the gateway directory (`gateway/`):

```
cd gateway
npx wrangler deploy --env staging
```

Verify both workers are live:

```
curl -s https://hlada-staging.<your-subdomain>.workers.dev/login -o /dev/null -w "%{http_code}\n"
# → 200

curl -s https://straumvakt-ocpp-staging.<your-subdomain>.workers.dev/health -w "\n"
# → ok
```

## 2. Provision an OCPP identity for the test charger

Log in to `hlada-staging` via the browser at `/login` (admin
credentials from your Cloudflare secrets). Then either use the
browser devtools to POST, or use curl from a machine that has an
admin session cookie:

```
curl -X POST https://hlada-staging.<your-subdomain>.workers.dev/api/admin/dev/provision-identity \
  -H "content-type: application/json" \
  -H "cookie: straumvakt_admin_session=<your-session-cookie>" \
  -d '{
    "displayName": "Test Site One",
    "identityString": "CP-STRMVKT-001",
    "connectorType": "Type2",
    "maxPowerKw": 22,
    "countryCode": "IS"
  }'
```

Response (201):

```json
{
  "ok": true,
  "orgId": "...",
  "orgSlug": "dev-xxxxxxxx",
  "hostId": "...",
  "propertyId": "...",
  "siteId": "...",
  "chargerId": "...",
  "ocppIdentityId": "...",
  "connectorId": "...",
  "identityString": "CP-STRMVKT-001",
  "password": "<64-char hex>",
  "note": "Copy this password into the charger's OCPP config..."
}
```

**Save `ocppIdentityId`, `connectorId`, and `password` — the password
will not be shown again.**

## 3. Configure the charger

On the charger's OCPP config page:

- **OCPP URL**: `wss://straumvakt-ocpp-staging.<your-subdomain>.workers.dev/ocpp/1.6/CP-STRMVKT-001`
- **OCPP version**: 1.6J
- **Auth username**: `CP-STRMVKT-001` (must match `identityString`)
- **Auth password**: the password from step 2.

Apply the config and reboot the OCPP module if the vendor requires it.

## 4. Verify heartbeat flow

Query Neon (or use `prisma studio` against the staging branch):

```sql
SELECT event_type, occurred_at
FROM events.event_log
WHERE aggregate_id = '<ocppIdentityId>'
ORDER BY occurred_at DESC
LIMIT 10;
```

Expected rows (approximately):

```
ocpp.raw.BootNotification       2026-04-24 20:00:00+00
ocpp.raw.StatusNotification     2026-04-24 20:00:01+00
ocpp.raw.Heartbeat              2026-04-24 20:01:00+00
ocpp.raw.Heartbeat              2026-04-24 20:02:00+00
...
```

`ocpp.ocpp_identities.last_seen_at` should update within a heartbeat
interval.

## 5. Verify ChangeConfiguration round-trip

Pick a non-destructive key that your charger supports. Most
Zaptec / Easee / generic OCPP chargers support
`HeartbeatInterval` (units: seconds).

Change to 120s:

```
curl -X POST https://hlada-staging.<your-subdomain>.workers.dev/api/admin/chargers/<ocppIdentityId>/change-configuration \
  -H "content-type: application/json" \
  -H "cookie: straumvakt_admin_session=<your-session-cookie>" \
  -d '{"key":"HeartbeatInterval","value":"120"}'
```

Response: `{"commandId":"...","status":"pending"}` (202).

Trigger the dispatcher:

```
curl -X POST https://hlada-staging.<your-subdomain>.workers.dev/api/admin/dispatcher/tick \
  -H "cookie: straumvakt_admin_session=<your-session-cookie>"
```

Response: `{"claimed":1,"acked":1,"retried":0,"failed":0,"skipped":0}`.

Query the event log for the result:

```sql
SELECT event_type, payload
FROM events.event_log
WHERE event_type = 'ocpp.command_result'
  AND payload->>'commandId' = '<commandId-from-above>';
```

Expected: one row. `payload.outcome` should be `"accepted"`, and
`payload.result.status` should be `"Accepted"` or similar per the
charger's vendor.

Confirm the change stuck by reading it back:

```
curl -X POST https://hlada-staging.<your-subdomain>.workers.dev/api/admin/chargers/<ocppIdentityId>/get-configuration \
  -H "content-type: application/json" \
  -H "cookie: straumvakt_admin_session=<your-session-cookie>" \
  -d '{"key":["HeartbeatInterval"]}'

# then tick, then query events.event_log for the resulting command_result.
# payload.result.configurationKey[0].value should be "120".
```

After this test completes, set `HeartbeatInterval` back to its
original value (usually 60 or 300) the same way.

## 6. Verify RemoteStart state change

Trigger remote start:

```
curl -X POST https://hlada-staging.<your-subdomain>.workers.dev/api/admin/chargers/<ocppIdentityId>/remote-start \
  -H "content-type: application/json" \
  -H "cookie: straumvakt_admin_session=<your-session-cookie>" \
  -d '{"connectorId":"<connectorId>","idTag":"TESTTAG"}'
```

Tick the dispatcher. Query the connector's status:

```sql
SELECT status, status_updated_at FROM ocpp.connectors WHERE id = '<connectorId>';
```

Expected transition: `Available` → `Preparing` (and sometimes →
`Charging` if the charger's state machine short-circuits when no
vehicle is present — vendor-dependent).

A `charging.sessions` row should appear with `status = 'in_progress'`.

## 7. Close the test session — valid zero-energy CDR

Get the OCPP transactionId the charger assigned (from the
`ocpp.raw.StartTransaction` event's CallResult payload, or by
inspecting the charger's UI).

Trigger remote stop:

```
curl -X POST https://hlada-staging.<your-subdomain>.workers.dev/api/admin/chargers/<ocppIdentityId>/remote-stop \
  -H "content-type: application/json" \
  -H "cookie: straumvakt_admin_session=<your-session-cookie>" \
  -d '{"transactionId": <the-txn-id>}'
```

Tick. The charger sends `StopTransaction`, the session row closes:

```sql
SELECT id, status, started_at, ended_at, energy_wh, stop_reason
FROM charging.sessions
WHERE id = '<session-id-from-start>';
```

Expected: `status='completed'`, `energy_wh=0` (no vehicle charged),
`stop_reason` populated. This is the CDR. Financial-retention events
for `session.started` and `session.stopped` are in `events.event_log`
permanently.

## Sprint 1.5 exit — what "done" looks like

1. Provision endpoint returns a password + row chain.
2. Real charger boots, heartbeats visible in log + `last_seen_at`.
3. ChangeConfiguration + GetConfiguration round-trip verified.
4. RemoteStart transitions `ocpp.connectors.status`.
5. RemoteStop produces a zero-energy CDR (closed session row).

If any step fails, capture the relevant log query and DO log
(Cloudflare dashboard → Workers → straumvakt-ocpp-staging → Live
Logs) before re-running.

## After the test

- Note findings in `docs/retros/sprint-01.md`.
- Leave the test identity alive for 1.4 / 1.5 regressions, OR
  invalidate it: set `ocpp.ocpp_identities.status = 'suspended'` in
  staging Neon. Do **not** delete rows — the event log references
  them.

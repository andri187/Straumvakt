## 1. The explicit requirement, and how it is met

> Deleting a charger during an active session initiates a stop and settles it with the driver; show pending until closure and sufficient evidence are confirmed.

Implemented as a durable, resumable **lifecycle request** (`assets.lifecycle_requests`, `src/lib/lifecycle/**`):
1. **Block new starts immediately**, atomically with the request: the engine refuses Authorize/StartTransaction for any device with an OPEN request (`startBlocked`), still recording a refused start as unauthorized evidence. Stops and meter evidence are NOT blocked, so the session being ended can finish.
2. **Initiate the stop**: `RemoteStopTransaction` is sent by the gateway to the device's CURRENT owning socket; the charger's CallResult/CallError is correlated; offline (no current socket), rejected, timeout and unavailable are distinct outcomes. **An accepted command is recorded but is never confirmation.**
3. **Confirmation = the durable `StopTransaction`** the engine commits (`stopped_received_at`). Until then the request is `stopping`.
4. **Close** the placement and connection identity in ONE transaction that re-checks "no open session", bumps the installation revision and writes the history row (device row and all history kept). Closing earlier is impossible by construction.
5. **Settle** through the retained costing consumer: `costed` | `held(reason)` (blocked energy, missing rate, …) | `not_applicable` (unauthorized). A held settlement is visible and does not hide or zero anything; the request shows `settling` until costing has decided.
6. **Failure is explicit**: a rejected/offline/timed-out stop is retried with backoff (10 s, 30 s, 2 min, 5 min; max 5) then `needs_attention` stating the session is NOT confirmed stopped; the same request resumes when the charger finally reports the stop.
**Unavailability, not a bypass:** if a session is open and no stop command path is bound, the removal is refused as `stop_unavailable` and nothing is written; the preview says so.

## 3. What was built

- **Domain** `src/lib/lifecycle/{model,plan,service}.ts`: transition table, pure planner (`planNext`: what is due, never an effect; settlement derived only from the costing consumer's durable state), service (`previewRemoval`, `requestRemoval`, `progressRemoval`, `cancelRemoval`, `listReturnable`, `returnDevice`). Optimistic version claim taken AFTER the effects but INSIDE the same transaction, so a worker that loses the race throws and its effects roll back.
- **Persistence** `drizzle-store.ts` + `assets.lifecycle_requests` + migration `0006_charger_lifecycle` (additive): one **open** request per device by a partial unique index; CHECKs for kind/state/version/completed-time/actor. Close locks the installation row `FOR UPDATE`.
- **Engine**: `TransactionTx.startBlocked` → Authorize/StartTransaction return `Blocked` (reason `service_blocked_removal`) while a removal is open; a blocked start still creates an unauthorized transaction row.
- **Gateway**: `engine-mode.requestStop` (current-socket only, 10 s bound, CallResult/CallError correlation, invalid transaction numbers refused), DO route `/command/stop`, and a **named `CommandEntrypoint`** (service-binding only; not routed by the public fetch handler).
- **API** `POST /api/cpo/lifecycle` (`preview | remove | progress | cancel | returnable | return`): session → same-origin → JSON → 8 KB cap → zod; no-store; mounted in the three allow-lists. `live.ts` wires the Drizzle store, the costing consumer, and an OPTIONAL `GATEWAY` stop binding (absent ⇒ stop unavailable).
- **Guard on the existing path**: the editor's plain Save detach now refuses (`validation`, wholly rolled back) when the device has an open session or an open removal — previously it detached regardless. The serial-collision message no longer states where else a device might be registered and points to "return the known charger / contact support".

## 5. Session and CDR history
- Each `ocpp_transactions` row keeps its sealed org/installation/device/placement and the authorization decision; the lifecycle closes the placement without touching them, and `observed()` correlates by device and transaction number, so a late stop/meter after the close still lands on the ORIGINAL transaction. Admission refuses a closed identity, so a late message from a removed device **cannot be received** after the identity closes — mitigated by closing only after the stop is confirmed; a bounded recovery path for messages after close is **not built** and is listed as a limitation, not hidden.
- Costing prices on the SEALED installation/org at the session's server start time (see the completion handoff). **Version retention of the terms is NOT proven**: the costing code looks up the agreement/rates in force at start time from today's tables; it does not copy the applied tariff/factor/payer version into the session. If a rate or agreement row is later edited in place, the explanation changes. This is the missing contract the brief asks to identify: a sealed `terms_snapshot` on the transaction (or on `agreements.billing_lines.computation_detail`, which already records rate code and cascade) is required before "sealed" can be claimed. Sponsor CDR access and the sponsorship-cutoff rule are not implemented here.
- A new organisation does not inherit another's CDRs by receiving a device (history is keyed to the sealed org); no read path for CDRs was added or changed.

## 6. Designs for what was NOT built
- **Cross-installation transfer:** requires (a) authority in BOTH organisations (or a platform operator) recorded as two approvals, (b) a single transaction that closes the source placement and identity, opens the destination placement, and re-keys the identity string (installation-key prefix changes) with an exclusion-constraint conflict check, (c) refusal while any session is open or a removal is open, (d) no automatic grant/sponsorship/readiness carry-over, (e) history rows in both installations. Test cases: concurrent transfer vs reattach, transfer with open session, destination identity taken, one org's approval only, source revision stale.
- **Installation close/archive:** states `open → closing (preview + block new starts on every charger) → (each charger: guarded removal) → closed` with `archived_at` set only after every charger's request is `completed` and no session is open or settlement pending; never a cascade delete; blocked while any child request is `needs_attention`. Needs a parent request type over `lifecycle_requests` (or an `installation_id`-scoped request kind) — not added.
- **Retirement-specific items not built:** distinct retirement permission, charger-side shutdown confirmation (0 A/offline-current), "service blocked centrally; device shutdown unconfirmed" display, retired-reconnect operator alert, backdating correction.

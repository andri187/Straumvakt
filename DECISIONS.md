# DECISIONS

One line per decision. Newest first.

This replaces the ADR habit for the market phase. The ADR-per-decision
ceremony produced 51 documents that exceeded what anyone could hold, so each
new question got answered fresh instead of looked up — which is how three
billing generations happened. See [FOCUS.md](./FOCUS.md) rule 8.

**How to add an entry:** date, one sentence, and the consequence if it is not
obvious. No template, no status field, no supersession chain.

**When to write an ADR instead:** only when a decision is genuinely
load-bearing *and* irreversible — a schema shape that will carry money, or a
boundary that other people will build against. Expect that to be rare. If you
are reaching for an ADR to think out loud, write the line here instead.

| 2026-08-28 | **Provenance is temporal-by-default, not a parallel audit system.** The model already closes rows rather than deleting them — placements, memberships, clauses — arrived at three separate times for three separate reasons. **Where a table is dated, the history IS the audit**, so the rule is: anything deciding money or access is dated and closed, never mutated, and a trigger-written audit covers only the mutable remainder (an org's address, a user's name). **Add transaction time alongside valid time** on those tables, so a backdated correction is visible as a correction rather than as history that always looked that way. **Humans get read-only credentials to production; only the application writes** — removing the ability rather than detecting the act, and it costs nothing. Rejected: full event sourcing (ceremony rather than safety at this size, and the benefit is already had on the tables that need it) and further internal tamper-proofing (**nothing inside a database defeats its owner**). **The customer-facing trust artifact is the invoice provenance block — what was measured, what a person asserted, which rate version — not the audit trail.** A signed document hash only if a customer asks. Consequence: the acceptance test "no row created by hand" is guaranteed by access control and the temporal model, and merely *reported* by a provenance query. |
| 2026-08-28 | **The target is a dress rehearsal of the whole product, not a first invoice — [the rehearsal definition](./docs/notes/2026-08-28-the-dress-rehearsal.md).** Aiming straight at an invoice produces one invoice hand-driven through a runbook for a customer re-onboarded by a script — which proves nothing about the product and has to be done again the day a UI exists. **The estate is wiped, chargers and charge logs completely, and the same physical chargers are re-onboarded from nothing through the real pathway.** No actor, charger, agreement or membership is created by hand; steps between may be mimicked for testing. **The line is: nothing that leaves the system is real, everything inside it is** — every write, screen, refusal, import and OCPP session is real; email, invoice delivery and payment status are captured rather than served. An invoice is produced, numbered and rendered, and reaches nobody who owes money. **Acceptance: no row in the database was created by hand**, every row traceable to a screen action and an audit entry — plus a second host org onboarded identically with nothing of theirs visible to the first, because isolation cannot be proven with one tenant. **Consequence: the UI lane moves to critical path** — it has had one dispatch in eighteen days and its branch has been unmerged since 11 August — and the re-onboard becomes the acceptance test for the onboarding UI rather than a data chore. | 2026-08-28 | **The legacy CDR and billing history is archived and cut, not carried — [ADR 0055](./docs/adr/0055-legacy-history-is-archived-not-carried.md).** The fresh start settled what the new system consumes; it did not settle what happens to the old system's history, so the old system is still running. `lib/agreement/billing-tick.ts` reads sessions through Prisma from a **scheduled handler at `index.ts:488`** and writes `agreementBillingLine` — the legacy billing generation is not dormant code, it is a cron that writes billing lines, and once `0002` is applied there are two writers with nothing deciding which owns a period. **Export the history to a checksummed, restore-tested archive; switch the writer off and delete it; read no legacy table.** The harvest protocol's step-3 parity obligation dissolves with it — parity against a history we have decided not to inherit protects an output nobody reads. **The archive is the retention mechanism, not the live database:** records underlying issued invoices carry a statutory retention period, but retention does not require them queryable in production; format is the accountant's call. **This collapses the Prisma retirement into the same round** — six of the eight surviving Prisma files are on that legacy path and become deletable rather than convertible, leaving only the two driver route files, which fail loudly. Executes after ADR 0054 items 1–6 are applied, because cutting history does not cut ingest. **Gated on one unanswered question: what actually invoices customer 1 today.** |
| 2026-08-20 | **A device is immortal, a placement is dated, and billing counts overlap — [ADR 0054](./docs/adr/0054-devices-placements-and-effective-dating.md).** A charger serial sits on exactly one installation at a time, but moves over its life: an owner relocates, a rental unit is re-subscribed to a new customer, a charger changes building mid-month. Three entities where there was one — an immortal `device` on a surrogate key holding the lifetime stats, a `device_identities` table because the OCPP identity is a Basic-auth credential and not a hardware fact, and `placements` as `device × installation × tstzrange` under `UNIQUE (device_id, period WITHOUT OVERLAPS)`. **The temporal key is load-bearing, not stylistic:** a partial unique index on the open row permits overlapping *closed* rows, and billing sums over overlap, so two hosts get invoiced for one charger with nothing raised. Sessions stay sealed and carry placement, site and tariff. Memberships are closed, never deleted — which is the move-out capability that had no owner, and which un-blocks the bill-the-roster option the active-driver packet had to reject on mechanics. **Retires the charger-identity access-grant decision: there is no grant model, a move is an explicit close-then-open.** Spec-aligned rather than invented — OCPI warns by name against using hardware identifiers as `EVSE.uid`, so a placement is what OCPI exports. Thirteen implementation changes are locked in the ADR; items 1–6 land before the Dalvegur re-onboard, which writes the first placements. Migrations `0002`/`0003` are unaffected. |
